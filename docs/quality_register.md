### DEF-001

外部 YAML 的 `id` 和 `type` 在重命名时被覆盖。用以下 `legacy.md` 样例复现。

```markdown
---
title: Legacy note
id: external-citation-23
type: research-article
custom: preserve-me
---
# 外部笔记正文
```

1. 打开该文件，用「重命名」把标题改为 `Renamed`，文件名栏输入 `renamed`。确认影响清单并执行。
2. 查看 `renamed.md` 的 YAML。`f3f04a3` 上的后台复现走了同一 `NoteRenameService`，两个原值均被替换，`custom` 仍在。
3. 修复后复测外部数据保护，并与已有 LinkNote 笔记作对照。保护场景验收原文件、字段和正文，成功重命名场景验收重开、同一 UUID、双链和反链。需要迁移字段时，按评审通过的映射验证原值可追溯。

`353fb43` 在生成重命名清单时检查会被改写的 `id`、`type`，遇到冲突直接提示字段。后台桌面测试从搜索结果进入重命名，确认两份原文件、搜索结果和图谱关系正确。存储回归同时确认外部笔记的正文仍能保存，原有字段保留。[存储入口](../src/main/java/linknote/storage/MarkdownNoteRepository.java) · [设计决定](design_decisions.md#dec-002)

### DEF-002

行内 HTML `<code>[[B]]</code>` 中的内容被提取为双链。以一篇名为 B 的笔记作对照，将下面一行写进 A。

```markdown
正常链接 [[B]]，HTML 示例 <code>[[B]]</code>，Markdown 代码示例 `[[B]]`。
```

1. 在 `f3f04a3` 上，直接以 `before <code>[[B]]</code> after` 调用 `MarkdownPreview.wikiReferences`，观察到一条已提取引用。
2. 修复后，A 的正常段落链接仍能跳转。行内 HTML 按现有的转义规则显示，Markdown 代码示例保持原样。索引只提取普通段落中的一处引用。
3. 重命名 B 后检查 A，只有普通段落里的引用发生改写。验收同一解析规则在预览、反链和重命名中的行为，并加一组 HTML 块与围栏代码的对照。

`353fb43` 让预览与索引共用对行内 HTML 的处理。测过嵌套标签、空元素、HTML 块及相邻的普通链接，也检查了标题或单元格中的未闭合标签对下一区域的影响。桌面流程已验证保存、搜索目标、改名与重开时，普通引用更新，HTML 代码示例保留。[Markdown 解析入口](../src/main/java/linknote/ui/MarkdownPreview.java) · [JavaFX 测试](../src/test/java/linknote/DesktopSmokeTest.java)

### DEF-003

`MarkdownNoteRepository.scan()` 会递归读入笔记库根目录 `assets/` 子树里的 `.md`。用包含一份普通笔记和一份附件的目录复现。

```text
test_vault/
  ordinary.md
  assets/
    attachment.md
```

1. 在 `f3f04a3` 上，用笔记库根目录初始化 `MarkdownNoteRepository`。`scan()` 的结果包含 `assets/attachment.md`。当前应用的 `scanFolder()` 读取单层目录，该测试中的附件未进入单层列表。
2. 修复后，把附件样例改为带普通笔记相同 UUID 和独有关键词的文件。递归扫描应保留普通笔记，无重复 UUID 报错，独有关键词也不能进入基于这一扫描结果的搜索或索引。
3. 同时复测 `.linknote/`、临时文件和正常笔记子目录。用例以笔记库根目录的 `assets/` 规则为准。

`353fb43` 的存储集成测试使用同一份递归扫描结果构建目录、搜索和链接索引。根目录附件中的重复 UUID 未影响正常笔记，附件专有词和引用也未进入结果。普通笔记子目录及其内部的 `assets/` 目录按原有规则读取。[目录扫描入口](../src/main/java/linknote/storage/MarkdownNoteRepository.java) · [存储测试](../src/test/java/linknote/NoteStorageTest.java)

## 联动验收场景

以用户的实际任务组织联动验收，记录起始文件、操作顺序、界面反馈和盘上结果。日常开发选与改动相关的场景。阶段和发布验收使用该版本的代表性完整流程。以下是场景定义，实际通过范围见 [验证记录](#验证记录)。

| 真实情境 | 从入口到结果的操作 | 验收要观察的结果 | 相关需求或用例 |
| --- | --- | --- | --- |
| 整理课程笔记 | 新建 A 并写入指向 B 的双链，保存后看反链和图谱。从搜索结果打开 B 并重命名。退出重开，再从 A 点击链接。 | 新文件名与引用路径正确，B 的 UUID 一致。新标题能搜到，反链和图谱仍指向 B。 | N02、N04–N08、T14、T17 |
| 编辑期间文件被外部修改 | A、B 已有关联时，修改 A 的正文，并在另一编辑器修改磁盘上的 A。尝试保存及切换，选择继续编辑。另走一次在重命名确认界面外部修改引用文件的流程。 | 冲突提示可操作，磁盘外部修改和编辑区草稿同时保留。失效的重命名清单停止提交。重新加载后，搜索和图谱与实际保存的文件一致。 | N02、N06、T13、T35、T36 |
| 读论文后写相关工作 | 新建 Paper，填作者和方法，保留未知的 DOI，写正文并保存。重启后搜索并打开，再用一篇普通 Note 链接它。 | 已填写的字段、未知状态和正文都能重开，普通 Note 的链接可跳转，Paper 反链可回到写作草稿。 | P01、V04、N04、N05、N08、T02、T17 |
| 发带图片的笔记给组员 | 导入两张来自不同目录的同名图，验预览，保存并导出。组员在另一台电脑解压到含中文或空格的目录后离线打开。 | 两张图内容正确，包内 Markdown 使用可解析的相对路径。另试缺图情形，检查提示和原有分享包。 | N12、V09、T39–T41 |
| 在代码笔记里补全 Java | 在 Java 围栏采纳候选，继续输入后文，保存并重开。再在普通段落输入相同前缀，并测试取消候选。 | 只在正确区块提示，采纳只替换当前前缀，已有后文保留。重开能看到已采纳并保存的结果，取消时正文保持原样。 | N13、V10、T42、T43 |
| 审核 AI 建议并写入笔记 | 一次用 Paper 摘要完成提取、逐项审核、保存和重开。另一次对一条公式请求补全，预览、确认插入并手动保存。用 Mock 延迟模拟切换笔记后仍收到建议。 | Paper 保留既有个人正文和未核验来源，LaTeX 保存后重开仍可渲染。过期建议无法写入当前笔记。分别记录真实调用和 Mock 的验证结果。 | A03、A09、V05、V11、T20–T24、T44、T45 |

验收时用测试库副本。涉及关闭应用后重开时，记录是重新创建窗口还是重新启动进程。跨机、离线、真实 API 等条件按实际观察登记。
