### DEC-001

**状态** 待评审，记录日期 2026-11-28。

V1.2 §5.6 设计了 `PaperNote extends Note`。当前 `Note` 是 Java `record`，被读写、重命名、索引、搜索和图谱共同使用。V04 需要增加结构化的 `PaperData`，并保留既有笔记数据与操作。[计划书 §5.6、§11](linknote_v1_2_development_plan.md) · [当前 Note 类型](../src/main/java/linknote/model/Note.java)

| 方案 | 实现和影响 |
| --- | --- |
| 继续使用继承设计 | 把 `Note` 改为普通 Java 类，保留通用数据和稳定取值接口，由 `PaperNote` 继承并持有 `PaperData`。需要复核原 `record` 的值比较行为，尤其是重命名确认后的快照比较和索引去重。 |
| 保留 `Note` 并组合 `PaperData` | 在通用笔记快照中表示类型和论文信息。普通笔记的论文信息为空。现有调用方继续用同一数据类型，静态类型和字段验证由模型约束。选用时同步更新 §5.6 和相关类图。 |

两种方案共用同一 Markdown 文件结构，继续使用 `type: note` 或 `type: paper`、稳定 UUID 及 Paper 的 `paper` 映射。验收覆盖旧普通笔记、已有 `type: paper` 文件、未知字段与值比较。选定方案后，再用 T02、T03、T14、T17 跑保存重开、重命名和搜索。

### DEC-002

**状态** 2026-11-28 在本地提交 `353fb43` 实施预检保护，外部元数据迁移的映射待评审。

外部 Markdown 可能已经使用 `id` 和 `type` 作为自己的字段。LinkNote 的正式 schema 也用这两个名字，分别保存稳定 UUID 和笔记类型。`f3f04a3` 会在重命名时补齐或改写部分值，已通过样例复现。[DEF-001](quality_register.md#def-001) · [计划书 §5.4–5.5](linknote_v1_2_development_plan.md)

| 方案 | 实现和影响 |
| --- | --- |
| 预检拦截冲突并提示导入 | 在确认写入前提示具体冲突字段，保留原路径和原文件。已有正式 LinkNote 文件和兼容的外部文件继续走重命名流程。冲突文件需要先处理导入。 |
| 经用户确认后迁移字段 | 制定保留外部字段和值的映射，显示转换预览。保存正式 UUID 和类型的同时保留原有信息及备份。需确定迁移格式、重开行为和回归用例。 |

本轮采用预检保护。外部文件如果已有与 LinkNote 规范冲突的 `id` 或 `type`，重命名在生成清单前提示具体字段并停止，原文件和引用保留。兼容的外部文件继续按现有格式重命名。若随后开展导入迁移，需评审字段映射及恢复方式。普通笔记重命名、现有 Paper 类型和 UUID 已做本地回归。[验证记录](quality_register.md#验证记录)
